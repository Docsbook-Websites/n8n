# Deploy n8n

n8n runs either as a managed service or on infrastructure you control. Both are production paths; they differ in who carries the operational work.

<!-- widget:cards -->

- [n8n Cloud](./cloud.md) — Managed hosting with a free trial and no server to run {cloud}
- [Self-hosting](./self-hosting.md) — Docker Compose, npm, and cloud providers {server}
- [Security and credentials](./security.md) — Secret storage, sharing, and access control {lock}

<!-- /widget -->

## Which one

Choose **Cloud** if you want to build automations rather than operate a service. Choose **self-hosted** if data residency, network isolation, or full configuration control are requirements rather than preferences.

The full comparison, including plan-by-plan features, is in [Choose how to run n8n](../get-started/choose-how-to-use-n8n.md).
